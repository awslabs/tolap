# TOLAP Policy Server — AWS infrastructure

CDK app that provisions everything the server needs: network, database, identity,
secrets, compute, and the console.

```bash
npm install
npx cdk bootstrap                 # once per account/region
npm run deploy
```

Outputs include the resolve endpoint URL, the console URL, and the ARNs of the two
secrets you need — the seeded administrator's credentials and the signing key.

## What it creates

| Stack | Contents |
| --- | --- |
| `TolapNetwork` | VPC, two AZs, private subnets with egress, VPC endpoints for Secrets Manager and ECR |
| `TolapDatabase` | Aurora PostgreSQL Serverless v2 (0.5–4 ACU), private, encrypted, 7-day backups |
| `TolapIdentity` | Cognito user pool, `tolap-admin` / `tolap-auditor` groups, app client with PKCE, **a seeded admin user whose credentials go to Secrets Manager** |
| `TolapServer` | Fargate service, internal ALB for the admin API, internet-facing ALB for `/v1/resolve`, signing key in Secrets Manager, schema migration on deploy |
| `TolapConsole` | S3 bucket plus CloudFront distribution serving the console |

## Topology

```
   administrators ──► CloudFront (console) ──┐
                                             ├──► internal ALB :8080  admin API
   (VPN / Direct Connect / bastion) ─────────┘         (Cognito JWT)

   remote installs ─────────────────────────────► public ALB :8081  /v1/resolve
                                                       (install credential)
```

The admin ALB is **internal**: the policy-authoring surface is reachable only from
inside the VPC or a connected network. `canonical-enforcement-spec.md` §13 states
policy authors are trusted administrators, so keeping that surface off the internet
matches the threat model the SDKs were designed against. `/v1/resolve` is public
because remote installs are, by definition, remote.

The console is static files on CloudFront and calls the admin API directly, so the
browser needs the same network reachability as any other admin client.

## The seeded administrator

You cannot use the console until some Cognito user is in the `tolap-admin` group, and
a chicken-and-egg is a poor first experience. So the deployment creates one
administrator and writes its username and a generated password to Secrets Manager:

```bash
aws secretsmanager get-secret-value \
  --secret-id "$(aws cloudformation describe-stacks --stack-name TolapIdentity \
      --query 'Stacks[0].Outputs[?OutputKey==`AdminSecretArn`].OutputValue' --output text)" \
  --query SecretString --output text | jq
```

The password is generated by CDK, never appears in a template or a log, and the user
is created with a **permanent** password so there is no forced-reset dance on first
sign-in.

Two things to do with it:

- **Turn on MFA.** The pool is configured with MFA optional and TOTP available; this
  account can author policy governing regulated data, so enrol it.
- **Treat it as a break-glass account.** Add your real users — ideally by federating
  a corporate IdP into the pool — and put them in `tolap-admin`. Leave this one for
  recovery, and rotate the secret when you no longer need it day to day.

## The signing key

Generated by Secrets Manager at deploy time (32 bytes, no punctuation that would
complicate shell handling) and injected into the task as `TOLAP_SIGNING_KEYS` under
the kid `initial`. It never appears in a template, an environment file, or a log.

To rotate, add a second key and flip the active kid — see
[`../docs/policy-server.md`](../docs/policy-server.md#rotating-the-signing-key). The
overlap means installs update without a flag day.

## Group membership

The task role is granted exactly one Cognito permission,
`cognito-idp:AdminListGroupsForUser`, scoped to this pool. That is what makes
group-scoped policy assignments resolve: `/v1/resolve` is called by an install on
behalf of a user, so there is no user token to read `cognito:groups` from and the
server asks the pool.

## Cost

Aurora Serverless v2 idles at 0.5 ACU and one Fargate task runs continuously, so
expect a small but non-zero standing bill, plus two ALBs and a NAT gateway. `npm run
destroy` removes everything; the database has `RemovalPolicy.SNAPSHOT`, so a final
snapshot is retained and is billed until you delete it.

## A note on `npm audit`

`npm audit --omit=dev` is clean. A full `npm audit` reports one high-severity finding
in `brace-expansion`, reached through `minimatch`, which `aws-cdk-lib` ships as a
**bundled** dependency — it is inside the published tarball, so an `overrides` entry
cannot replace it and no available `aws-cdk-lib` version carries a patched copy. CDK
is build-time tooling that emits CloudFormation and ships nothing into the deployed
artifact, which is why it lives in `devDependencies` here and why the production
audit is the meaningful one. Revisit when CDK updates its bundle.
